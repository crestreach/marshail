# MARSHAIL v1.2.0

*Workbench mode, a closed feedback loop, and agents that know how they run.*

A feature release that adds a second way of working — iterative, plan-less **workbench sessions** — next to the staged lifecycle, makes "close the feedback loop" a core principle, and tightens how agents are run, what they load, and what they log.
It also carries the knowledge-layer refactor that splits each implementation into a reading guide and a maintenance guide and makes the agents implementation-neutral.

## What changed

- **Workbench mode.**
  Not every piece of work is a change that can be framed and planned up front.
  In workbench mode the user works round by round with the new interactive orchestrator [`marshail-workbench-driver`](../marshail-files/agents/marshail-workbench-driver.md); there is no `delivery-plan.md`, the session keeps `workbench-session.md` under `.marshail/work/wb-<date>-<slug>/`.
  It drops the stages, not the discipline: every task in a round still runs in a fresh-context specialist, knowledge is used and kept in sync, the session is logged and resumable, and a PR out of a session is still preceded by Verify.
  A staged change can take a **detour** into a session — recorded in the plan with the new `[DETOUR yyyy-mm-dd]` marker, folded back by the planner when the session ends — and a session can be promoted into a change.
- **Close the feedback loop — new core principle.**
  An agent that produces something runs it (tests, build, the code, the app, the UI flow) and reports what it observed before handing back; human verification covers only what the agent genuinely cannot reach.
  Woven into the testing strategy, Dev-QA, `implementation-report.md` ("how the agent verified this"), and the implementer, verifier and reviewer.
- **Three ways an agent runs.**
  As the **session agent** (the user talks to it directly), as a spawned **subagent** (a bounded task; cannot talk to the user), or **inline**.
  Rule: spawn for bounded tasks, never for a conversation.
  The conversational roles — `marshail-driver`, `marshail-workbench-driver` — run as session agent or inline via the new main-session skills [`marshail-drive`](../marshail-files/skills/marshail-drive/SKILL.md) and [`marshail-workbench`](../marshail-files/skills/marshail-workbench/SKILL.md) (run inline when intent is clear, ask once when it is not); the driver is spawned only for hands-off end-to-end runs.
  Switching between the two orchestrators is a **session handover** (state on disk plus a one-line prompt), never a spawn.
- **`marshail-delegate-to-driver` narrowed; new hands-off fallback.**
  The delegate skill now triggers only on hands-off end-to-end intent; everything interactive goes through `marshail-drive`.
  [`marshail-drive-end-to-end`](../marshail-files/skills-fallback/marshail-drive-end-to-end/SKILL.md) is its inline counterpart for tools without subagents.
- **Fallback skills are now equivalent to delegate skills.**
  Every `skills-fallback/marshail-*` skill carries the same trigger phrases and call contract (context needed, produced, then) as its `marshail-delegate-to-*` counterpart; only where the agent's workflow runs differs.
  The spec records why skills exist alongside agents: they carry the caller-side contract an agent description cannot.
- **Knowledge implementation split into reading and maintenance guides.**
  `knowledge.representation_ref` now points at a short **reading guide** (standard load tier) that names the root entry and links a **maintenance guide** (full tier, curator only).
  Markdown Spine's organizing, depth, size, staleness and update rules moved to [`knowledge-markdown-spine-maintenance.md`](../marshail-files/references/knowledge-markdown-spine-maintenance.md); its size caps moved to a new top-level `markdown_spine:` config section so the shared `knowledge:` section stays neutral.
- **Agents are implementation-neutral and list only what the caller passes.**
  No agent or skill names the default knowledge implementation or its field names any more.
  Inputs sections list only caller-passed artifacts; everything an agent loads itself is defined by its load tier, which every agent now states explicitly.
  Framer, specifier and helper moved from the minimal to the standard tier.
- **`marshail.md` is reference, not startup context.**
  The spec belongs to no load tier; only `marshail-helper` reads it in full.
  Every link into it carries a section anchor, and agents read just the linked section.
  The dispatch-by-spawning rule moved from the activation protocol into `ENTRYPOINT.md`.
- **Run logs are history plus a cross-run cache.**
  Each agent's `logs/<agent>.log.md` stores what it did and caches research, findings, decisions and pitfalls; a fresh-context run decides from its task whether to read them instead of redoing the work.
- **Smaller fixes.**
  The working folder is now always archived on finalize (the `knowledge.autonomy: auto` delete clause is gone); agent and skill descriptions containing `: ` are quoted so YAML clients load them; the Spine reading guide target is ~100 lines.

## Upgrade notes

Re-run the installer, then re-promote and re-sync assets.

- **Config migration (`.marshail/config.yml`).**
  The Markdown Spine size caps moved from `knowledge.root_index_max_lines`, `knowledge.subindex_max_lines`, `knowledge.topic_max_lines` to a new top-level `markdown_spine:` section with the same keys.
  The installer adds the new section with defaults and offers to drop the old keys; if you had changed any of the caps, copy your values into `markdown_spine:` by hand.
  `knowledge.representation_ref` keeps its value (`references/knowledge-markdown-spine.md`), which is now the reading guide.
- **Promote and sync.**
  Run `marshail-promote-assets` and then the cyncia sync so your tools pick up the new agent and skills (`marshail-workbench-driver`, `marshail-drive`, `marshail-workbench`, `marshail-drive-end-to-end`), the regenerated fallback skills, and the narrowed `marshail-delegate-to-driver`.
- **Behaviour change: `marshail-delegate-to-driver`.**
  It now triggers only for hands-off end-to-end runs.
  Interactive or collaborative driver use, and resuming a change, go through `marshail-drive`; if you have prompts or docs that invoke the delegate skill for interactive work, point them at `marshail-drive` (or select `marshail-driver` as your session agent).
- **`AGENTS.md` snippet.**
  Step 2 of the merged-in snippet now says to read the knowledge root entry named by the active implementation's reading guide instead of hard-coding `INDEX.md`; re-merge it from `.marshail/AGENTS.md` if you want the neutral wording.
- **Custom knowledge implementations.**
  If you replaced Markdown Spine, split your reference into a reading guide (pointed at by `representation_ref`) and a maintenance guide it links, and move implementation-specific settings into your own top-level config section.

## Install

From the root of your target repo:

```bash
curl -fsSL https://raw.githubusercontent.com/crestreach/marshail/main/scripts/install-marshail.sh | bash
```

Then run the `marshail-init` skill once to integrate MARSHAIL into the repo.
